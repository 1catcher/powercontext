# 数据库系统复习笔记（第 8 章：索引）

## 8.1 为什么需要索引
全表扫描的代价随行数线性增长。索引把查找从 O(n) 降到 O(log n) 级别，
代价是写入时维护索引结构和额外磁盘空间。

## 8.2 常用索引结构
- B+ 树：范围查询友好，叶子节点链成链表，适合等值与范围扫描。
- 哈希索引：只支持等值查询，不支持范围，冲突需要拉链或开放寻址。
- 倒排索引：面向全文检索，词项 -> 文档 ID 列表（posting list）。
- 向量索引：面向语义相似度检索，常见 HNSW / IVF 类近邻图结构。

## 8.3 混合检索
把全文匹配（BM25）与向量相似度（余弦）结合，是 RAG 系统的标准做法。
两种来源的分数需要归一化后再融合，常见做法是倒数排名融合（RRF）。
